# BK4829 - Binary-Verified Application Notes

Reverse-engineered register map and operational sequences for the **BK4829**
RF transceiver (Beken Corporation) as used in the **Radtel RT-950 Pro**.

> **Provenance disclaimer**: The BK4829 has no public datasheet. Every value
> in this document was extracted from OEM firmware disassembly (V0.18 and V0.27)
> using radare2. The BK4819 (an older Beken chip) has a published register list
> and application notes - it is **believed** to be register-compatible, but this
> is NOT proven. Any BK4819-sourced information is explicitly marked
> **[BK4819 ASSUMED]** and should be treated as an unverified hypothesis.
>
> Where we know the register value the OEM uses but NOT what the individual bits
> mean, we document the raw value and the context in which it appears. We do NOT
> infer bit meanings from BK4819 docs unless marked.

---

## 1. SPI Interface

**Source**: V0.18 binary @ 0x0800AF04 (BK4829_Init), V0.27 @ 0x0801B9CC (set_mode)

The RT-950 Pro uses **two BK4829 chips** on a shared bit-bang SPI bus via GPIOE:

| Signal | Pin | GPIO | Verified |
|--------|-----|------|----------|
| SEN1 (chip 0 select, active-low) | PE8 | 0x40011800 bit 8 | FW_VERIFIED |
| SCK (clock) | PE10 | 0x40011800 bit 10 | FW_VERIFIED |
| SDA (bidirectional data) | PE11 | 0x40011800 bit 11 | FW_VERIFIED |
| SEN2 (chip 1 select, active-low) | PE15 | 0x40011800 bit 15 | FW_VERIFIED |

### 1.1 SPI Frame Format

**Source**: V0.18 spi_write/spi_read functions (disassembled bit-bang loops)

Each transaction is a **24-bit frame**, MSB-first:

```
Bit  23      22:16          15:0
     R/W     Register       Data
     1=write 7-bit addr     16-bit value
     0=read  (0x00-0x7F)
```

- **Write**: MCU drives SDA for all 24 bits. SENv, clock out 24 bits, SEN^.
- **Read**: MCU drives bits [23:16] (R/W=0 + addr), then switches SDA to input
  and clocks in 16 data bits. SEN^.

### 1.2 SPI Timing

**Source**: OEM bit-bang loop analysis (GPIO set/clear with inline NOP delays)

- Clock: bit-banged at ~1-3 MHz (depends on MCU clock, currently 120 MHz)
- CPOL = 0 (clock idle low), CPHA = 0 (data sampled on rising edge)
- SDA direction change: MCU reconfigures GPIO CRH between output and input
  for read transactions (visible as GPIO CRH write between TX and RX phases)

at power-up. Every register address and value below is extracted directly from

not BK4819 datasheet definitions.

### Phase 2: Read-Modify-Write of REG 0x40

```c
reg40 = read(0x40);
write(0x40, (reg40 & 0xF000) | 0x04D2);
```

Preserves the top 4 bits (factory-programmed?) and sets bits [11:0] = 0x4D2.
This register is used for FSK mode configuration (seen again in APRS code).

### Phase 3: Post-RMW Configuration (2 writes)

| # | Reg | Value | Note |
|---|-----|-------|------|
| 37 | 0x7D | 0xE912 | MIC sensitivity / AGC |
| 38 | 0x48 | 0xB3FF | RF gain - changed from Phase 1 value 0xB3BF |

### Phase 4: Calibration Sequence (16 writes to REG 0x09)

A 16-step calibration sweep. The upper nibble increments 0x0-0xF while the
lower 12 bits vary per step. This appears to be an internal VCO/filter
calibration driven by the MCU.

```
Step  0: 0x006F    Step  4: 0x4050    Step  8: 0x8041    Step 12: 0xC0E4
Step  1: 0x106B    Step  5: 0x5047    Step  9: 0x9037    Step 13: 0xD0CB
Step  2: 0x2067    Step  6: 0x603A    Step 10: 0xA025    Step 14: 0xE0B5
Step  3: 0x3062    Step  7: 0x702C    Step 11: 0xB017    Step 15: 0xF09F
```

**Pattern**: Upper nibble = step index (0-F). Lower 12 bits = calibration
coefficient - values decrease monotonically per group, suggesting frequency-
dependent compensation.

### Phase 5: AF Response Coefficients (6 writes)

| # | Reg | Value | Note |
|---|-----|-------|------|
| 39 | 0x74 | 0xE61C | AF response / CTCSS TX config |
| 40 | 0x44 | 0x8F88 | AGC control 1 |
| 41 | 0x45 | 0x3201 | AGC control 2 |
| 42 | 0x75 | 0xE61C | AF response / CTCSS detect (same value as 0x74) |
| 43 | 0x54 | 0x91C1 | AF response |
| 44 | 0x55 | 0x3040 | AF response |

## 3. Register Map - Binary-Verified

Every register below has been **observed in OEM firmware disassembly**. We
document: the register address, every value the OEM writes, and the operational
context. Where the purpose is unknown, we say so.

### 3.1 System Control

| Reg | OEM Values | Context | Binary Address |
|-----|-----------|---------|----------------|
| 0x00 | 0x8000 | Init only - chip reset/power | 0x0800AF04 |
| 0x01 | 0x0000 | Init only - GPIO direction clear | 0x0800AF04 |
| 0x02 | 0x0000 | APRS FSK stop - disables TX | 0x0801EC54 |

### 3.2 Frequency Control

| Reg | OEM Values | Context | Binary Address |
|-----|-----------|---------|----------------|
| 0x38 | freq_hz[15:0] | VCO frequency low word | 0x0801ED40 |
| 0x39 | freq_hz[31:16] | VCO frequency high word | 0x0801ED40 |

**Frequency programming**: The OEM writes a 32-bit value split across REG_38
(low 16 bits) and REG_39 (high 16 bits). The exact relationship between this
value and RF frequency in Hz is **not fully verified**.

**[BK4819 ASSUMED]**: On the BK4819, frequency = value x 10 Hz (i.e., 14500000
for 145.0 MHz). Our code uses the same formula. This has NOT been independently
verified on the BK4829, but the OEM code structure is consistent with this
interpretation.

| Reg | OEM Values | Context | Binary Address |
|-----|-----------|---------|----------------|
| 0x28 | 0x0B40 | RSSI config - init only | 0x0800AF04 |
| 0x29 | 0xAA00 | RSSI/AGC - init only | 0x0800AF04 |
| 0x0C | (read) | Status readback register | Throughout |

**REG_0C readback fields** (verified from operational code):
- **Bit 0**: FSK TX complete (polled during APRS transmission)
- **Bit 1**: Squelch open indicator (read at 0x0801559A via GPIO_ReadPin pattern)
- **Bit 14**: CTCSS/DCS tone detected (read in ctcss_detected / dcs_detected)
- **Bits [15:0]**: Full register also read as raw RSSI value

### 3.8 Master Enable Register (REG 0x30)

> See also: APRS mode value 0xC3FA in S4.8.

**Source**: V0.27 @ 0x0801BC2C (bk4829_set_mode)

This register controls which subsystems are active. The OEM uses 5 distinct
values, selected by operating mode:

| Mode | REG_30 Value | Context |
|------|-------------|---------|
| Standby | 0x0000 | All subsystems off |
| FM RX | 0xBFF1 | Normal receive |
| FM TX | 0xC1FE | Normal transmit |
| AM RX | 0x0302 | AM receive mode |
| Scan/APRS | 0xC3FA | Wideband receive / FSK |

**What we DON'T know**: The individual bit meanings within REG_30. The BK4819
datasheet describes 16 individually named enable bits (VCO, PLL, PA, MIC, RX,
TX, etc.). **[BK4819 ASSUMED]** - the bit assignments MAY be the same, but we
have not verified individual bits. We only know the composite values above
produce the expected behavior.

### 3.9 GPIO Direction (REG 0x33)

| Reg | OEM Values | Context | Binary Address |
|-----|-----------|---------|----------------|
| 0x33 | read-modify-write | radio_set_modulation - toggles GPIO bits | radio.c |

The OEM reads REG_33, modifies specific bits, and writes back. This controls
the BK4829's own GPIO pins (NOT the MCU GPIOs). Exact bit mapping unknown.

### 3.10 TX Power (REG 0x36)

**Source**: V0.27 @ 0x0801BD64, table at 0x0802B724

| Level | REG_36 Value | Effect |
|-------|-------------|--------|
| Low | 0x8E79 | Minimum PA power |
| Mid | 0xA498 | Medium PA power |
| High | 0xF016 | Maximum PA power |

**Note**: The OEM also has a PA bias ramping path at 0x0800B700 that uses
bias values (0x52, 0xAB, 0x104) via DMA for smooth power transitions. The
direct REG_36 write is the simpler equivalent.

**What we DON'T know**: Actual dBm output levels per REG_36 value. The BK4819
datasheet provides a power-vs-register table - **[BK4819 ASSUMED]** this may
apply, but actual dBm output depends on the PA design and is unverified.

### 3.13 AGC / Detection

| Reg | OEM Values | Context | Binary Address |
|-----|-----------|---------|----------------|
| 0x44 | 0x8F88 | AF/AGC coefficient - init Phase 5 | 0x0800AF04 |
| 0x45 | 0x3201 | AF/AGC coefficient - init Phase 5 | 0x0800AF04 |
| 0x46 | 0x6050 | Detection/bandwidth - init only | 0x0800AF04 |
| 0x47 | 0x6042 \| LUT[mode] | RF AGC - changes per mode | 0x0801B9CC |
| 0x48 | see below | RF gain - calibration dependent | 0x0801BC2C |
| 0x49 | 0x2AB2 | AGC - fixed at init, never changed | 0x0800AF04 |

**REG_47 lookup table** (extracted from 0x0802B80C):

| Mode Index | LUT Value | REG_47 Final | Mode |
|------------|----------|-------------|------|
| 0 | 0xDB27 | 0x6042 \| 0xDB27 | FM RX chip 0 |
| 1 | 0xBB94 | 0x6042 \| 0xBB94 | FM RX chip 1 / APRS |
| 2 | 0x6616 | 0x6042 \| 0x6616 | Reserved |
| 3 | 0xEB4F | 0x6042 \| 0xEB4F | AM RX |

**REG_48 per mode**:
- **AM RX**: Fixed 0xB0A3
- **FM RX/TX**: 0xB00F | (calibration_value << 4), where calibration_value

- **Init**: 0xB3BF (Phase 1), then 0xB3FF (Phase 3)

### 3.15 Tone Control (REG 0x51)

**Source**: V0.27 @ 0x0800A85A (CTCSS), 0x0800A864 (DCS), 0x0801EC08 (CPS mute)

| REG_51 Value | Mode | Context |
|-------------|------|---------|
| 0x904A | CTCSS TX/RX | Enable CTCSS, gain=74 |
| 0x8033 | CDCSS TX/RX | Enable CDCSS, gain=51 |
| 0x0300 | CPS mute | RF mute during programming |
| 0x0000 | Off | All tone processing disabled |

When DCS + negative polarity: 0x8033 | (1 << 13) = 0xA033.

### 3.16 Sub-Audio Frequency / Code Word

| Reg | OEM Values | Context |
|-----|-----------|---------|
| 0x07 | freq_word & 0x1FFF | CTCSS: frequency control word |
| 0x07 | 2775 | CDCSS: bit clock for code transmission |
| 0x08 | code[11:0], then 0x8000 \| code[22:12] | CDCSS: 23-bit code word (two writes) |

**CTCSS frequency formula** (observed in code @ 0x0800A85A):
```
freq_word = (tone_freq_tenths_hz x 2065) / 1000
```
Example: 67.0 Hz -> tone_freq = 670 -> (670 x 2065) / 1000 = 1383

**[BK4819 ASSUMED]**: This formula matches the BK4819 app note's CTCSS
coefficient of 20.64897, which rounds to our 2065/1000 integer ratio.

## 4. Operational Sequences

### 4.1 Power-Up

1. Assert SEN1 and SEN2 high (deselect both chips)
2. Configure PE10/PE11 as push-pull outputs, PE8/PE15 as push-pull outputs
3. Run init sequence (Section 2) on each chip independently

### 4.2 Tune to Frequency

**Source**: V0.27 @ 0x0801ED40

1. Write REG_38 = freq_hz[15:0]
2. Write REG_39 = freq_hz[31:16]
3. PLL locks automatically (no status poll observed in OEM code)

### 4.3 Switch to RX

**Source**: V0.27 @ 0x0801BC2C

1. Write REG_30 = mode value (0xBFF1 for FM, 0x0302 for AM)
2. Write REG_47 = 0x6042 | LUT[mode_index]
3. Write REG_48 = calibration-based value
4. (AM only) Read-modify-write REG_70 for AM demodulator

### 4.4 Switch to TX

**Source**: V0.27 @ 0x0801BC2C, 0x0801BD64

1. Write REG_30 = 0xC1FE (TX enable)
2. Write REG_47 = 0x6042 | LUT[2] (TX AGC)
3. Write REG_48 = calibration-based gain
4. Write REG_36 = power level (0x8E79 / 0xA498 / 0xF016)

### 4.5 CTCSS TX Enable

**Source**: V0.27 @ 0x0800A85A

1. Compute freq_word = (tone_freq x 2065) / 1000
2. Write REG_51 = 0x904A (CTCSS mode, gain=74)
3. Write REG_07 = freq_word & 0x1FFF
4. Write REG_37 = 0x9F1F (enable sub-audio)

### 4.6 DCS TX Enable

**Source**: V0.27 @ 0x0800A864

1. Write REG_51 = 0x8033 (CDCSS mode, gain=51; | 0x2000 if inverted)
2. Write REG_07 = 2775 (CDCSS bit clock)
3. Write REG_08 = code_word[11:0]
4. Write REG_08 = 0x8000 | code_word[22:12] (load trigger)
5. Write REG_37 = 0x9F1F (enable sub-audio)

### 4.7 RF Mute (During CPS Programming)

**Source**: V0.27 @ 0x0801EC08

1. Write REG_51 = 0x0300 (mutes RF path, prevents interference during flash I/O)

### 4.8 APRS TX Sequence

**Source**: V0.27 @ 0x0801EB8C (init), 0x0801EEF4 (send), 0x0800C97C (trigger)

1. Select Chip 1 (APRS VFO) via vtable at `0x20000B88` - set `r0=1` at `0x0800E7D0`
2. Write REG_30 = **0xC3FA** (all signal paths enabled for APRS TX)
3. Configure FSK registers (REG_58, 70, 72, 5C, 5D, 59, 3F) per Section 3.19
4. Build AX.25 frame with MIC-E position encoding
5. Write frame data to FIFO (REG_5F) as 16-bit words
6. Hardware handles NRZI encoding, bit stuffing, flag generation
7. Poll REG_0C bit 0 for TX completion
8. Write REG_02 = 0x0000, REG_3F = 0x0000, REG_59 = 0x0028 (stop)

### 4.9 APRS RX (Hardware FSK Demodulation)

**Source**: V0.27 @ 0x0801EBE4 (init), 0x0800C890 (digipeater match)

1. Select Chip 1 (APRS VFO)
2. Configure FSK RX: REG_3F = 0x3000, sync word = 0xFB72 4099 (REG_5A/5B)
3. BK4829 correlates incoming AFSK against sync word in hardware
4. Poll REG_0C bit 1 for RX data ready
5. Read demodulated data from FIFO (REG_5F) as 16-bit words
6. Digipeater path matching at `0x0800C890` validates AX.25 addresses
7. Valid packet flag `0xAA` stored at `[0x2000A2E0 + 0x11]`
8. Display buffer copy to `0x20010504`

## 5. Chip Assignment

The RT-950 Pro uses two BK4829 chips with distinct roles:

| Chip | Select Pin | Primary Role |
|------|-----------|--------------|
| Chip 0 (SEN1 = PE8) | Active-low PE8 | Main VFO (VFO-A and VFO-B) |
| Chip 1 (SEN2 = PE15) | Active-low PE15 | APRS / secondary monitoring |

Both chips share the same SCK (PE10) and SDA (PE11) lines. The MCU selects
which chip to communicate with by asserting the appropriate SEN line.

**Runtime chip selection**: A vtable at RAM `0x20000B88` holds read/write function
pointers for the active chip. Code at `0x0800E7D0` switches chips:
- `r0=0` -> Chip 0 (read=`0x0801F28D`, write=`0x0801F359`) - Main VFO
- `r0=1` -> Chip 1 (read=`0x0801EC4D`, write=`0x0801F3AD`) - APRS VFO

**Dual-watch**: When enabled, the MCU alternates reading RSSI from both chips
to detect signals on both VFOs simultaneously.

## 7. BK4829 vs BK4819 - What We Know

### 7.1 Similarities (Observed, Not Proven)

- Register addresses appear to overlap (0x00-0x7F range)
- SPI protocol is identical (24-bit frame, same R/W bit position)
- CTCSS/DCS frequency formula appears to match
- FSK/AFSK subsystem appears to operate similarly
- REG_30 appears to serve the same master enable function

### 7.2 Known Differences

- **PLL/LO registers**: RT-950 init values **differ dramatically** from BK4819:

  | Register | RT-950 (BK4829) | BK4819 | Impact |
  |----------|-----------------|-----------------|--------|
  | 0x10 | 0x0318 | 0x007A | Major PLL difference |
  | 0x11 | 0x033A | 0x027B | Major LO difference |
  | 0x14 | 0x0210 | 0x0019 | Major PLL difference |
  | 0x7B | 0x73DC | 0x8420 | Unknown (IF/AGC?) |

  These differences could indicate: (a) the BK4829 has a different PLL
  architecture, (b) different XTAL frequency, or (c) different frequency
  plan. This is the strongest evidence that the BK4829 is NOT a drop-in
  register-identical replacement for the BK4819.

- **REG_37 default**: RT-950 sets bit 15 = 1 at init (sub-audio ON).
  BK4819 sets bit 15 = 0 (sub-audio OFF). May cause unintended RX behavior
  if not accounted for.
- **IF bandwidth**: The OEM RT-950 firmware uses a **single fixed** REG_1C
  value (0x07C0). BK4819 firmware dynamically switches REG_1C per channel
  bandwidth (12.5K/25K). This could mean: (a) the BK4829 handles bandwidth
  differently, (b) the OEM simply doesn't change it, or (c) the BK4829
  ignores REG_1C and uses a different mechanism.
- **AGC**: The BK4829 OEM uses **mode-based** REG_47/48 selection (via a
  4-entry lookup table). BK4819 uses **band-based** selection (different
  values per frequency band). The register may work the same, but the OEM
  uses it differently.
- **TX power**: BK4829 OEM uses 3 fixed REG_36 values. BK4819 uses per-band
  calibrated power tables. Again, may be the same register, different usage.
- **REG_40**: The BK4829 init preserves the top 4 bits via RMW. BK4819
  writes REG_40 directly. This could indicate hardware revision differences.
- **Scrambler bit**: RT-950 uses REG_31 bit 0. BK4819 uses REG_31 bit 1.
  Potential conflict with VOX (bit 1 on BK4819).

### 7.3 Unverifiable Without Hardware

The following BK4819 datasheet claims **cannot** be verified from binary
analysis alone and require hardware testing:

- Package pinout (QFN-32 pin assignments)
- XTAL requirements (26 MHz assumed from BK4819)
- Supply voltage ranges
- Current consumption (RX/TX/sleep)
- Absolute RSSI dBm calibration
- Actual TX output power in dBm per REG_36 setting
- Sensitivity specifications

## 9. Gaps and Future Work

1. **Individual bit-field verification**: For most registers, we only know the
   composite values the OEM writes. We need hardware testing (or exhaustive
   binary cross-referencing) to verify individual bit functions.

2. **Frequency formula**: The freq_hz -> REG_38/39 relationship needs hardware
   verification. Program a known frequency, measure RF output, confirm scaling.

3. **REG_1C bandwidth**: Determine if the BK4829 supports dynamic IF bandwidth
   switching or if it uses a different mechanism than the BK4819.

4. **RSSI calibration**: REG_0C values need correlation with actual dBm via
   a signal generator for meaningful S-meter readings.

5. **Sleep/power save**: The OEM likely has a power-save mode writing REG_30
   = 0x0000 periodically. Full power management sequence needs tracing.

6. **GPIO register (REG_33)**: The BK4829's own GPIOs are used for something
   (likely antenna switch or PA control). Full RMW patterns need mapping.

7. **DTMF**: REG_0C bit 15 is described in BK4819 docs as DTMF detect. We
   haven't verified this from OEM binary usage patterns yet.

8. **VOX**: REG 0x71 threshold table documented in S3.23. Full state machine
   at 0x0801EF4C traced but anti-VOX dual-VFO interaction needs hardware testing.
